# Volvo On Call CN v3.2.1

本版本汇总 v3.2.0 之后的完整审计加固，重点修复控制确认、Home Assistant 生命周期、依赖声明、隐私日志与故障恢复问题。建议所有 v3.2.0 用户升级。

## 控制与轮询可靠性

- 锁车、车窗、引擎、尾门、天窗、家充和即插即充等控制命令使用有界强制刷新确认，整体最多等待 30 秒，不再因完整轮询超时叠加而卡住数分钟。
- 每个控制命令都要求目标数据源在命令发送后产生新的成功更新；车辆临时不在账户列表、数据源回退缓存或本地乐观状态均不能误报为确认成功。
- 瞬时传输或单源失败会在总时限内继续重试；最终无法确认时向 Home Assistant 返回明确错误。
- 并发强制刷新使用调用身份令牌，取消、关机、队列满或等待刷新锁超时时不会遗留令牌，也不会吞掉其它控制命令的刷新请求。
- 慢速数据源仍按周期节流，但失败后会在下一轮立即重试，不再等待完整的健康、里程或车辆偏好刷新周期。

## Home Assistant 生命周期与凭据

- `VolvoCoordinator` 显式绑定当前 `config_entry`，兼容新的 Home Assistant `DataUpdateCoordinator` 生命周期要求。
- 首次刷新失败或任务取消时会移除未完成的协调器、关闭 API/gRPC 客户端并保留其它配置条目，避免重试期间泄漏资源。
- 更新监听器跟随配置条目卸载自动移除，避免失败重试后监听器累积。
- 账号或密码变化改为整体重载配置条目，协调器与缓存车辆不会短暂混用新旧 API 会话。
- 重新认证与正常启动使用相同的 `data + options` 优先级；在 Options 中更换过账号后，会验证实际运行账号而不是旧账号。

## 安全、隐私与依赖

- 每车持久化 Store 使用 VIN 哈希键，并兼容迁移旧的明文 VIN 文件。
- 旧 Store 读取或删除失败时只记录异常类型，不再把可能包含 VIN 的完整文件路径写入日志。
- protobuf 响应和控制调用日志继续统一脱敏，避免 VIN、设备标识及令牌进入调试日志。
- manifest 直接声明生成代码所需的 `protobuf>=5.27.2`；`grpcio-tools` 仅用于生成代码，不再作为运行时依赖。
- CI 从 manifest 安装集成依赖，避免工作流与发布清单再次漂移。

## 正确性与效率

- 移除车辆名称缺失时的重复 `listBindCar` 请求，并安全接受空白或缺失的 `seriesName/modelName`。
- 未取得有效定位时返回未知坐标，而不是错误显示为 `(0, 0)`。
- Lovelace 卡片资源版本由文件内容哈希生成，升级后不会继续命中旧缓存。
- 修复充电控制名称、数字实体状态更新、GPS SourceType、充电上限失败退避及车辆从账户解绑后的可用性处理。
- gRPC 增加 keepalive；密码登录冷却和失效 refresh token 状态可跨重启正确延续。

## 升级说明

- 无需删除并重新添加集成。
- 升级后请重启 Home Assistant，以加载新的 Python 依赖与协调器生命周期逻辑。
- 如果使用容器或手动复制安装，请确认完整替换 `custom_components/volvooncall_cn` 目录，而不是只覆盖个别文件。
