# Volvo On Call CN v3.2.2

本版本集中处理一轮安全、性能与长期运行稳定性审计中确认的问题。升级不需要重新添加集成；旧版 Options 中重复保存的账号密码会在下一次保存设置或重新认证时迁移到唯一配置来源。

## 安全与认证

- Options 不再显示或允许修改用户名，密码字段始终为空；留空表示保持不变。
- Protobuf 运行时下限提升至 `6.33.5`，不再允许安装 `CVE-2025-4565` 与 `CVE-2026-0994` 覆盖的旧版本。
- 只修改扫描间隔或动力类型不再调用认证接口。首次配置和新密码验证成功后的 token 通过内存一次性交给正式 API 实例，避免连续两次密码登录。
- 删除条目会取消延迟写入并删除该条目使用过的私有 token Store；凭据变化会先清理旧运行实例的会话。
- refresh token 使用 URL 编码；超时、429 和 5xx 会保留 refresh token，不再错误降级为密码登录。
- 日志脱敏新增 `accessToken`、`globalAccessToken`、`jwtToken`，并完整遮盖带空格的引号值。
- Hassfest 与 HACS GitHub Actions 固定到完整提交 SHA，Python 测试和 Ruff 工具固定版本。

## 性能

- 多辆车最多并发更新 2 辆，并按并发批次数动态设置有界周期预算，慢车不会串行饿死后续车辆。
- 持续失败的数据源按 30、60、120 秒递增退避，最高 5 分钟；成功后立即恢复正常节奏。
- 家充桩和订单缓存改用单调时钟、按 VIN/connector 单航班；慢响应返回后才开始计算 TTL。
- 缓存失效使用 generation，控制命令完成后，旧的飞行中响应无法重新写回旧 `tradeNo`。
- HTTP 429 不再在 0.5/1 秒内快速重放，会读取 `Retry-After` 并阻止协调器提前访问。
- 只有降低且启用充电上限时才立即强制刷新；上调、重复保存或设为 100% 不产生额外全量请求。

## 稳定性

- 协调器节流改用 `time.monotonic()`，NTP 校时或宿主机时间回拨不会冻结轮询。
- BatteryService 与家充桩使用独立缓存、健康状态和 generation；一个来源失败不会覆盖另一个来源的最后有效数据。
- 所有本轮数据源失败时会进入协调器失败计数和有限缓存宽限，不再把构造默认值报告为成功状态。
- 超过 1 小时的来源缓存会删除并将其拥有的状态清为未知；单辆车持续失败超过宽限时，即使同账号其他车健康也会变为不可用。
- 空 gRPC stream、缺少必要 protobuf payload、控制命令没有服务端确认都会明确失败。
- SoC 的 NaN、Infinity、负值或大于 100 的值不会触发自动停止充电；BatteryService 的非有限关键数值不会覆盖好缓存。
- 初次车辆列表为空时由 Home Assistant 重试设置；运行中绑定新车辆会触发一次受控重载以创建实体。
- 普通传感器在平台建立时立即读取首次刷新数据，不再等待第二轮轮询才显示状态。

## 动态轮询（可选，默认关闭）

- Options 新增“动态轮询”开关和折叠的“动态轮询设置”：用车 60 秒、充电 5 分钟、白天 10 分钟、夜间 30 分钟，时段与间隔均可调整；多个条件同时满足时取最短间隔。
- 用车模式由可配置的时间段或引擎运行状态触发，熄火后保持 5 分钟；充电模式覆盖夜间充电。
- 轮询会提前到更快时段的开始时刻；失败后 2 分钟重试，部分数据源失败时最多快速重试 3 次。
- 按轮询次数节流的数据源（健康告警、里程、昵称）增加按时间的上限，长间隔下不会被拉长到数小时。
- 长间隔下来源缓存的有效期按当前模式间隔顺延，单次轮询失败不会立即把门锁状态清为未知。
- “连接状态”传感器新增 `polling_mode` 与 `polling_interval` 属性。未开启时行为与之前完全一致。

## 验证

- Python 单元与集成回归：196 项。
- Ruff、`compileall`、依赖一致性检查和 Node 前端测试均纳入发布前检查。
- CI 新增前端 Node 测试步骤。

## 仍需注意

- 本项目是非官方公开客户端，仓库中的应用签名常量不能作为真正的秘密；根治需要服务提供方采用适合公开客户端的授权机制。
- 远程控制后的确认仍会强制刷新账号范围数据；极高频自动化应自行设置节流。
- 家充地址与订单摘要属于个人数据并可能进入 Recorder 和备份，边界见 [SECURITY.md](../../SECURITY.md)。
- 本版本完成的是静态、模拟传输和 Home Assistant 测试环境验证；真实车辆、真实充电桩及长时间断网恢复仍需运行验证。
